## Notes on mapping decisions

- **Letter suffix has two meanings in this file**:
  - `#Na` / `#Nb` where the *behavior text is identical* = same behavior split into multiple tactic rows (multi-tactic split — the standard convention). Examples: `#13a`/`#13b`, `#15a`/`#15b`, `#16a`/`#16b`, `#21a`/`#21b`, `#24a`/`#24b`/`#24c`.
  - `#Nb` where the *behavior text differs from `#N`* = an **adjacent observable** inserted after `#N` without renumbering the rest of the chain. Examples: `#4b` (attacker cert on the sideloaded DLL, sitting alongside `#4`'s sideload), `#7b` (custom-exception control-flow hop after `#7`'s window check). These aren't multi-tactic splits — they're distinct behaviors at the same chain position.
- **#4** kept only under Stealth (T1574.001). In current ATT&CK, T1574.001's tactics are Persistence / Privilege Escalation / Stealth — Execution is not one of them, so an "Execution / T1574.001" row emitted by the mapping pass was dropped.
- **#4b** (T1553.002 — self-signed cert) is a **build-time property** with runtime observability at DLL load / Authenticode validation. Placed adjacent to `#4` because the signature is checked whenever `wsdapi.dll` maps (in `EssosUpdate.exe`, `regsvr32.exe`, and `waitfor.exe`).
- **#7b** (T1622 — custom exception) reflects `handler.cpp:181` throwing `CustomException` after the sandbox checks pass, caught in a `catch` block that calls `RegisterSelf()`. It's a control-flow obfuscation, not a data-artifact — the malicious routine never appears on the straight-line CFG.
- **#13** and **#14** both keep T1055.001 despite adjacency: #13 is the LOLBAS invocation observable (`mavinject` command-line + parent), #14 is the resulting cross-process DLL load observable (module loaded into `waitfor.exe`). Downstream (`assign-category`) can decide whether they're redundant enough to collapse into one scored row.
- **#19** left unmapped — `CoCreateGuid` for generating a victim identifier has no clean ATT&CK match; treated as supporting computation for #20 and #22 rather than a scored behavior. (MITRE 2025 Mustang Panda scenario mapped this to T1106 Native API; we diverge because T1106 for a single API call dilutes the tag — the discriminative signal lives in the persistent write at #20, not the GUID synthesis itself.)
- **#17** mapped to T1620 Reflective Code Loading only. Process Injection variants (T1055.*) were considered but T1620 fits better because the RX region is created by the same thread that runs it (same-process reflective load), not injected across processes.
