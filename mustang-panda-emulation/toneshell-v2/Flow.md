## Notes - multi-tactic splits

- **#1**: spearphishing attachment delivery (Initial Access) + user double-click of `.lnk` to execute (Execution) - fan-out kept in one cell.
- **#4**: DLL side-loading is cross-listed in Execution and Stealth (same TID) - fan-out kept in one cell.
- **#11, #14**: SSN resolution / shared-section injection cross-listed in Stealth and Execution - fan-outs kept in one cell.
- **#17**: `CoCreateGuid` generates an internal implant identifier; no ATT&CK technique covers random-GUID-based implant identity generation.
- **#21 → #22 / #23 / #25**: single dispatch routine fans into exec (Execution), download (C2), and upload (Exfiltration).
- **#23 → #24**: download write is staged under `.stl` (masquerade) then renamed in-process; rename mapped to T1036.008. When the destination itself ends in `.stl`, staging and rename are skipped (direct write passthrough).
- Legacy regsvr32 + mavinject path intentionally absent - `TONESHELL_DIRECT_SYSCALL` unconditionally defined for `wsdapi` (`src/wsdapi/CMakeLists.txt`); `register.cpp` not in the wsdapi source list.
